title: Audit Log
description: Cryptographically chained audit logging for enterprise compliance and security investigations.

The audit log records every mutating action taken within your organization or projects. It provides security teams and compliance auditors with an append-only, chronologically ordered ledger of who did what, when, and from where.

## Accessing the audit log

Audit logs can be inspected from the web console:
- **Organization Audit Log**: Navigate to **Organization Settings** -> **Audit Log** (`/:organizationSlug/audit-log`). Accessible only to organization **Owners** and **Admins**.
- **Project Audit Log**: Navigate to **Project Settings** -> **Audit Log** (`/:organizationSlug/:projectSlug/audit-log`). Accessible to project **Owners**, **Admins**, and **Members**.

Audit logs are also queryable programmatically by the [AI Context Agent](/self-host/agent/) using the `audit_events` inspection tool.

## Logged events

Telmoni records mutations across identities, organizations, projects, and integrations:

| Category | Typical Events |
| :--- | :--- |
| **Authentication & Sessions** | Password logins, OIDC SSO assertions, session revocations, password changes. |
| **Organization Lifecycle** | Organization creation, renames, ownership transfers, deletion requests, and restorations. |
| **Members & Permissions** | Member invitations, role promotions/demotions, member removals, and invitations declined or accepted. |
| **API Keys & Integrations** | API token creation, token rotations, and token revocations. Slack, Discord, and webhook connector configurations. |
| **Projects** | Project creation, project renames, project deletions, and project ownership transfers. |

## Event structure

Every audit log entry contains structured metadata:

- **Actor**: The authenticated user who initiated the action (user ID, name, email address). Actions initiated by automated platform routines or maintenance sweeps are recorded with actor `system`.
- **Action**: A standardized identifier representing the mutation (e.g., `member.invited`, `api_key.created`, `project.deleted`).
- **Target**: The resource acted upon (resource type and unique identifier).
- **IP Address & User-Agent**: The network origin and client details of the request.
- **Timestamp**: Recorded in UTC when the transaction committed.

Entries are ordered chronologically, newest first.

## Cryptographic hash chaining and integrity verification

Telmoni uses cryptographic hash chaining across audit log rows:

- Each audit log row includes a SHA-256 hash calculated over the current event
  and the hash of the preceding event, forming an unbroken chain per organization.
- Audit rows are emitted inside the exact database transaction that applies the
  mutation: if an operation fails or rolls back, no audit entry is written.
- A nightly verification sweep walks each organization's hash chain to ensure no
  records have been altered, skipped, or truncated out of sequence.

## Retention

In the hosted platform, audit records are retained for at least **730 days** (2 years). 

For self-hosted instances, audit logs are partitioned into monthly tables (`created_at`). Retention is governed by your database backup policies and whether you run partition maintenance scripts. See [Production Maintenance](/self-host/production/#audit-log-partition-rotation) for details on scheduling `telmoni rotate`.
